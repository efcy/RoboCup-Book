\chapter*{How to use this book}
\markboth{How to use this book}{How to use this book}
\addcontentsline{toc}{chapter}{How to use this book}

This is the practical companion of \emph{Road to RoboCup}. That book explains the concepts (mathematics, Linux, Python, neural networks, control, the rules of the Humanoid Soccer League and reinforcement learning with mjlab). This book has one goal: a \textbf{Booster K1} that plays in the Humanoid Soccer League with a program that \emph{you} wrote, in Python, and that you understand completely. You build it by \textbf{following along}.

\textbf{The code.} All the code of this book lives in its own repository, \coderepo\guess{} (the Python package inside is called \pkg). There is one git tag per chapter, for example \texttt{ch09-blackboard}, so you can always compare your version with a working one. Python is not the fastest language for a robot, and we will measure where this hurts (Chapter~\ref{k:loops}); it is the language in which you can read every line.

\textbf{Structure.} Every chapter has the same shape: \emph{what you need}, numbered \emph{steps}, a \emph{check} that tells you whether the step worked, \emph{if it does not work} (typical errors), \emph{what to remember}, and a few \emph{practice problems} with answers at the end of the book.
\begin{enumerate}[nosep,label=\textbf{Part~\Roman*:},leftmargin=4.2em]
  \item \textbf{Workshop:} your workstation, the robot, the SDK, the model, and three hardware jobs (power supply, back cover, jerseys). The hardware chapters do not depend on the code; a group that is not programming this week can do them.
  \item \textbf{Robot code foundations:} the repository and deployment, the blackboard, a fake robot, ROS~2 input, two loops, the debug tool \emph{robotcontrol}, logging and replay, the GameController.
  \item \textbf{Motion:} walking, deploying a learned policy safely, driving the robot from robotcontrol, your own motions.
  \item \textbf{Playing soccer:} perception, localisation, behaviour.
  \item \textbf{Match day:} health monitoring and the checklist.
  \item \textbf{Bonus:} video analysis.
\end{enumerate}

\textbf{Two milestones.} \emph{Milestone one} (end of Chapter~\ref{k:beh}, first version): the robot listens to the GameController, stands, walks to the ball and kicks it. \emph{Milestone two}: a full team that plays a match under the rules. Every chapter says which milestone it serves.

\textbf{References to the concepts book.} A chapter title in quotation marks with a small \textsuperscript{\textcolor{cupnavy}{\sffamily\scriptsize RtR}} is a chapter of \emph{Road to RoboCup}; read it when you want the why behind a step.

\textbf{Boxes.} A grey box lists \emph{what you need}. An orange box is a \emph{step} to carry out, a green box the \emph{check}, a red box \emph{what to do if it does not work}. A blue \emph{Key idea} box contains the rule to remember.

\textbf{Marked guesses.} This book was drafted without a K1 on the desk. Facts about the K1, its SDK and its software that could not be checked are marked with \guess{} or put in a yellow box titled \emph{Not verified on a real K1}. Check them against your robot and the current Booster documentation, and fix the book (it is in git too). Where the text says ``I ran it'' or quotes results, the code was run on a laptop with Python~3.13 (never on a K1) and the numbers come from those runs. Other listings, in particular everything that talks to the SDK or to ROS~2, are sketches that were not run; expect to fix details.

\textbf{Decisions taken in this draft.} Four choices still have to be confirmed by the team; the book uses these defaults: (1) the robot code runs on the K1's own computer, robotcontrol on a laptop; (2) milestone one walks with Booster's built-in walking controller through the SDK, so the low-level command rate of the SDK does not matter yet; (3) milestone one comes before the full team; (4) the code repository is called \coderepo{} with one tag per chapter.

\textbf{Safety first.} A humanoid robot falls, pinches fingers and has strong motors. Read the safety rules of Chapter~\ref{k:box} before you switch on anything, and the safety box of Chapter~\ref{k:power} before you build anything that touches power.
