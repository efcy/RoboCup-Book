\begin{verbatim}
import numpy as np
F, CX, CY, D = 554.0, 320.0, 240.0, 0.13
R_CL_OPT = np.array([[0, 0, 1], [-1, 0, 0], [0, -1, 0]])
def pixel_to_map(u, v, d_px, T_map_base, T_base_cam,
                 ball_z=0.0, base_height=0.83, tol=0.15):
    Z = F * D / d_px
    p_opt = np.array([(u - CX) * Z / F, (v - CY) * Z / F, Z])
    p_cam = np.append(R_CL_OPT @ p_opt, 1.0)
    p_map = T_map_base @ T_base_cam @ p_cam
    if abs(p_map[2] - (ball_z - base_height)) > tol:
        return None                  # physically impossible
    return p_map[:3]
\end{verbatim}
  With the transforms of the chapter, \texttt{pixel\_to\_map(400, 300, 24, \ldots)} returns $(2.433,\,3.809,\,-0.832)$; for $v=150$ (the ball seemingly high above the floor) it returns \verb!None!. The check (in the example the floor is at $z=-0.83$ because \verb!base_link! is at $z=0$) catches wrong distance estimates (a wrongly detected object of the wrong size, e.g.\ a bright spot at the ceiling, is far off the floor), wrong camera calibration or a wrong tilt of the head, and wrong frames or signs.
